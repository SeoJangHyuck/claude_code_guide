# 챕터 3: 도구 변천사 + 하네스 엔지니어링 (4슬라이드 / 6분)

> 톤 가이드: 기획안 6·7번 통합. 본인 변천사 → 일반화 비유(말 안장) → 3단계 차이 → 메시지. 비개발자 청중도 끄덕일 수 있게 비유 위주로. 슬라이드 용어는 덱 전체와 같게: hook은 장에서 처음 나올 때 "정해진 순간 자동 실행되는 동작", 권한은 "권한 설정(허용·금지 목록)", "호출" → "꺼내 씀", 강제 표현은 "정해진 순간 반드시 실행(Hook)·설정대로 차단(권한 설정)".

(장 표지 부제: "하네스 = 말에 채우는 안장·마구 — 사람이 개입하는 양이 줄어드는 진화." — 목차·표지에 먼저 나오는 '하네스'를 여기서 한 줄로 풀이. 이전 부제 앞부분 "프롬프트의 끝, 워크플로우의 시작"은 발표 제목과 같아 뺌)

---

## 슬라이드 3-1 — 본인 변천사 (1분 30초)

**핵심 메시지**: "나도 처음부터 Claude Code를 쓴 게 아니다. 청중과 똑같은 길을 거쳐 왔다."

**본문 콘텐츠**:

```
[ 헤더 ]
저도 처음부터 Claude Code는 아니었습니다
여러분처럼 ChatGPT로 시작해 Claude Code까지 옮겨왔습니다.

             Step 1                    Step 2                       Step 3 · 지금
             ChatGPT          →        Cursor              →        Claude · Claude Code
             ───────                   ──────                       ───────────────────
언제부터:    2024.06 ~                 2024년 말 ~                  2025년 ~
한 줄 회고:  "프롬프트 잘 짜면         "내 코드를 편집기에서         "프롬프트가 아니라
              답이 나오던 시대"         같이 짜주는 시대"             워크플로우를 짜는 시대"
쓰는 방식:   웹 채팅 ·                 AI 코드 편집기 ·             VS Code 확장 · 폴더 전체
             매번 새 프롬프트          열린 파일 인식                + 작업 절차 저장
```

**발표 노트 (1분 30초)**:
> "저도 처음부터 Claude Code를 쓴 게 아니었어요. 2024년 6월부터 ChatGPT로 시작했어요. 프롬프트만 잘 짜면 답이 나오던 시대였죠. 그러다 그해 말부터 Cursor라는 AI 코드 편집기(IDE)를 썼어요. 열어 둔 파일을 보고 내 코드를 같이 짜주는 도구였습니다. 그러다 2025년에 Claude Sonnet 신모델이 나오면서 Claude로 갈아탔고, 자연스럽게 Claude Code까지 이어졌습니다. Claude Code는 VS Code 확장으로도, 터미널 명령(CLI)으로도 쓸 수 있고, 열린 파일 하나가 아니라 폴더 전체를 보면서 Skill·Hook·Subagent 같은 기능으로 작업 절차를 저장해 둡니다. Claude Code에서 결정적으로 달라진 게 하나 있어요. 더 이상 매번 '프롬프트'를 짜지 않습니다. 한 번 '워크플로우'를 짜두면 그 다음부터는 그냥 꺼내 쓰기만 합니다. 이 차이가 오늘 1시간의 핵심이에요."

**시각 표현 메모**:
- 가로 3단 비교. 화살표로 연결.
- 각 단: 시점 + 회고(인용) + 쓰는 방식 한 줄. IDE·CLI·Sonnet 같은 세부 용어는 발표 노트로.
- 마지막 단(Claude · Claude Code) 강조색.

## 슬라이드 3-2 — 말 안장 비유 도입 (1분)

**핵심 메시지**: "엔지니어링은 말이 목적지에 도달하는 방식의 진화."

**본문 콘텐츠**:

```
Metaphor · 비유 한 장

목적지에 가야 하는 말(馬)이 있다고 칩시다.

[ 채찍(Prompt) ] → [ 길(Context) ] → [ 안장(Harness) ]

AI 엔지니어링은 결국,
그 말을 어떻게 목적지까지 보낼 것인가의 진화입니다.
```

**발표 노트 (1분)**:
> "이걸 좀 직관적으로 말씀드리려고 비유 하나만 가져왔어요. 목적지에 가야 하는 말이 한 마리 있다고 가정해봅시다. 우리가 흔히 말하는 'AI 엔지니어링', '프롬프트 엔지니어링', '컨텍스트 엔지니어링', 요즘은 '하네스 엔지니어링'이라는 말까지 나오는데요, 이게 다 결국 '말을 어떻게 목적지까지 보낼 것인가'의 진화입니다. 다음 슬라이드 하나로 정리해 드리겠습니다."

**시각 표현 메모**:
- 텍스트 4줄만. 큰 글자.
- 알약 3개는 비유 말(채찍·길·안장)을 앞에, 영어 이름을 괄호에 — 비개발자가 영어 세 단어만 보고 넘기지 않게. 영어 이름은 다음 슬라이드 카드 제목(프롬프트·컨텍스트·하네스 엔지니어링)과 이어짐.
- 그림은 다음 슬라이드에서 한꺼번에 (말 안장 일러스트 1장).

## 슬라이드 3-3 — 3단계 비교 (3분)

**핵심 메시지**: "프롬프트 → 컨텍스트 → 하네스. 각 단계는 사람이 매번 개입하는 양이 줄어드는 진화다. 그리고 컨텍스트와 하네스 사이엔 원리적 차이가 있다."

**본문 콘텐츠**:

```
[ 헤더 ]
엔지니어링의 진화 — 사람이 개입하는 양이 줄어든다
매 순간 명령(채찍질) → 한 번 가르치기(길) → 절차 자체를 도구화(안장).

[ 1단계: 프롬프트 엔지니어링 ]
🐎 채찍질로 이끌기
사람이 매 순간 명령. 말은 그때그때 따라감.
→ 같은 일을 매번 또 시켜야 함

[ 2단계: 컨텍스트 엔지니어링 ]
🐎 길을 알려주기
한 번 가르치면 말이 다음에도 그 길을 안다.
→ 메모리 · 사내 자료 참고

[ 3단계 · 지금: 하네스 엔지니어링 ]
🐎 안장과 마구를 채우기
일하는 절차 자체를 도구화. 한 번 채워두면 매번 채찍질할 필요 없음.
→ Skill(절차서) · Hook(정해진 순간 자동 실행되는 동작) 등

────────────────────────────────────────────────
왜 결정적으로 다른가
────────────────────────────────────────────────
                  부탁하는 설정                   반드시 작동하는 설정
                  ─────────────                   ───────────────────
지키게 하는 법:   지침 파일로 부탁 (CLAUDE.md)    정해진 순간 반드시 실행 (Hook)
막는 법:          AI가 판단                       설정대로 차단 (권한 설정)
────────────────────────────────────────────────
Skill을 꺼낼지는 AI가 정함 — 꼭 지킬 일은 Hook·권한 설정(허용·금지 목록)으로
```

**발표 노트 (3분)**:
> "1단계, 프롬프트 엔지니어링. 채찍질에 비유할 수 있어요. 사람이 매 순간 명령하고, 말은 그때그때 따라갑니다. ChatGPT 창에 매번 새 프롬프트를 짜는 게 이 단계예요. 문제는 같은 일을 매번 또 시켜야 한다는 점입니다. 2단계, 컨텍스트 엔지니어링. 한 번 길을 가르치면 다음에도 그 길을 압니다. RAG(관련 사내 문서를 찾아서 AI에게 함께 넣어 주는 방식), 메모리, 사내 지식 주입 같은 게 여기 들어가요. 3단계, 그리고 지금 우리가 살고 있는 단계, 하네스 엔지니어링입니다. 말에 안장과 마구를 채우는 거예요. 말이 어떻게 달려야 하는지를 절차로 박아둡니다. Skill(절차서)과 Hook(정해진 순간 자동 실행되는 동작)에 Subagent, MCP, Plugin까지 다 이 안장 역할이에요. 하나씩은 5장에서 보여드립니다. 그런데 여기서 한 가지만 더 짚고 넘어갈게요. 아래 표의 두 칸, '부탁하는 설정'과 '반드시 작동하는 설정'은 원리가 달라요. CLAUDE.md 같은 지침 파일은 Claude한테 '이렇게 해줘'라고 부탁하는 겁니다. 모델이 알아서 따를 수도 있고, 잊어버릴 수도 있어요. 이건 옛 방식이라서가 아니라 역할이 달라서입니다. 그래서 5장에서는 CLAUDE.md를 제일 먼저 익힙니다. 반면 Hook은 정해진 이벤트가 일어나면 Claude Code가 스크립트를 직접 실행합니다. 예를 들어 파일을 편집할 때마다 린트가 자동으로 돌아가도록 Hook을 걸어두면, Claude가 잊어버리거나 건너뛸 수가 없어요. 막는 쪽도 같습니다. 하지 말아야 할 일을 CLAUDE.md에 적어 두면 지킬지는 AI가 판단하지만, 권한 설정(허용·금지 목록)의 금지 목록에 넣으면 그 목록에 걸리는 작업은 설정대로 차단됩니다. 표에는 없지만 읽는 시점도 달라요. CLAUDE.md는 대화를 시작할 때 전문을 다 읽고, Skill은 설명 한 줄만 늘 올라가 있다가 쓸 때 본문을 읽습니다. 다만 Skill이나 Subagent는 Claude가 설명을 보고 꺼내 쓰는 거라 여전히 모델 판단이 들어갑니다. 반드시 지켜야 하는 규칙은 Hook이나 권한 설정으로 거는 게 맞아요. 정확히 말하면 반드시 지켜지는 건 스크립트를 직접 실행하는 command 형 Hook이나 권한 설정의 deny(차단) 규칙이고, 다른 모델에게 판단을 맡기는 prompt·agent 형 Hook은 여기서 빠집니다. 이 차이가 '부탁'과 '반드시'의 차이입니다. 요즘은 ChatGPT 데스크톱 앱의 Work·Codex에도 Hook이 들어와 있어서, 도구 이름보다 이 원리로 기억해 두시면 됩니다."

**시각 표현 메모**:
- 세로 3단 카드. 각 카드 4줄 구조.
- 3단계 카드(하네스)에 "지금" 라벨로 강조.
- 카드 아래 구분선 + 2행 비교표 (작은 글씨, 표 형태) + 표 아래 보충 한 줄 (Skill을 꺼낼지는 AI가 정함 — Subagent·command Hook·deny 규칙 같은 세부는 발표 노트로).
- 비교표 머리는 시대 구분(컨텍스트/하네스) 대신 방식 구분(부탁하는 설정 / 반드시 작동하는 설정) — CLAUDE.md가 '옛 방식'으로 읽혀 5장 "CLAUDE.md부터 익히기"와 어긋나 보이지 않게. 행은 "지키게 하는 법"·"막는 법" 2개. 이전 표의 '읽는 시점'(CLAUDE.md 전부 읽음 / Skill 필요할 때만 본문)은 '반드시 작동하는 설정' 칸에 맞지 않아 발표 노트로 옮김.
- 강제 표현은 덱 전체와 같게 "정해진 순간 반드시 실행(Hook)·설정대로 차단(권한 설정)". "Claude Code가 강제"는 청중에게 'AI가 강제'로 읽혀 옆 칸 "AI가 판단"과 모순처럼 보이므로 쓰지 않음.
- 말 안장 일러스트 1장만 슬라이드 우측 작게 (그림 사용 한정).

## 슬라이드 3-4 — 그래서 지금은 (30초)

**핵심 메시지**: "프롬프트 한 줄이 아니라 워크플로우를 짠다."

**본문 콘텐츠**:

```
프롬프트 한 줄이 아니라
워크플로우를 짭니다.

한 번 짜두면
다음 주에도, 옆자리 동료에게도 그대로 넘깁니다.
```

**발표 노트 (30초)**:
> "정리하면, 워크플로우를 짭니다. 한 번 짜두면 다음 주에도, 옆자리 동료에게도 그대로 넘깁니다. 오늘 1시간은 그 워크플로우를 어디에, 어떻게 짜는지에 대한 이야기입니다."

**시각 표현 메모**:
- 텍스트 2블록.
- 마지막 줄에서 챕터 4(도구 비교)로 연결.
- 그림 없음.
