② 작업
내 PC 폴더를 따로 올리지 않고 바로 작업

대화·읽은 내용은 암호화되어 Claude 서버로 전송

웹 채팅은 작업 전 파일 업로드 필요

AI 학습 사용 여부는 요금제·설정 따라

→ 권한 설정(허용·금지 목록)은 5장

③ 자산화·검증
반복 작업은 한 번 만들어 재사용, 작업 전후는 자동 점검

→ 5장 skills · agents · hooks

작업 폴더째 공유(개인 설정 파일 제외)

내 작업 폴더/ (VS Code에서 연 폴더) ├── .claude/ │ ├── CLAUDE.md ① 작업 폴더의 헌법 (매번 자동으로 읽힘) │ ├── skills/ ② 반복 작업 절차서 (필요할 때 꺼내 씀) │ │ └── 내-skill-이름/ │ │ └── SKILL.md │ ├── rules/ ③ 주제·폴더별 규칙 │ │ └── 내-rule-이름.md │ ├── settings.json ④ 권한 설정 + hook(정해진 순간 자동 실행되는 동작) │ ├── settings.local.json (개인 설정 파일) │ └── agents/ ⑤ subagent (보조 작업자) │ └── 내-subagent-이름.md ├── .mcp.json ⑥ MCP (외부 서비스 연결) ├── my-plugin/ ⑦ plugin (나눠 줄 묶음 원본 — 이 자리에선 동작 안 함) │ ├── .claude-plugin/plugin.json │ └── skills/ 등 └── (엑셀·보고서 등 내 파일)

Chapter 8 — 추천 플러그인: superpowers 1 / 1
superpowers — 검증 단계를 기본 절차로 넣는 플러그인
AI가 건너뛰기 쉬운 확인 4단계를 거치도록 지시 — 강제 아님, 코드 작업 중심.
🧠 brainstorming
만들기 전
질문을 하나씩 하며 의도·성공 기준 확인 → 설계 승인 후 시작
→ 잘못된 방향으로 시작하는 일 감소
🧪 test-driven-development
코드 작성 전
테스트(합격 기준)부터 작성 → 통과할 만큼만 코드 작성
→ '다 했다'의 기준이 명확
🔍 systematic-debugging
오류 발견 시
바로 고치지 않고 원인부터 — 오류 읽기·재현·정상 코드와 비교
→ 임시방편 수정 감소
✅ verification-before-completion
완료 직전
검증 명령(테스트 등)을 직접 실행해 결과 확인
→ 확인 없는 '완료' 선언 감소
💡 왜 추천하나
설문 1순위 고민(60%): AI 결과물 신뢰성·환각·검증 부담. 확인을 습관으로 만드는 도구 — 보고서 수치·출처 대조는 사람 몫.
